# V0.2 plan

Goal: store careers as dated race records, reason over them, and import notable horses from single Wikipedia articles. V0.1 behavior stays intact for horses that only have a W/DH/L list or a career summary.

## Before starting

Ask the owner these questions. Each one blocks the milestone noted in brackets.

1. Do walkovers count as wins for streaks and unbeaten records? Suggested default: yes, with a flag so a clue can exclude them. [Milestone 1]
2. Disqualifications: the plan records the official result, so a horse placed first and then demoted counts as a loss and a promoted horse counts as a win. Confirm. [Milestone 1]
3. Racing age: Northern Hemisphere horses age on 1 January and Australian and New Zealand horses on 1 August. The plan uses a per-country table with those entries. Which other countries should be added? Do not add entries from memory without the owner confirming them. [Milestone 2]
4. Which three Wikipedia articles to save as importer fixtures. Suggested mix: one modern horse with a full infobox, one 19th-century horse, one horse from outside Britain and North America. [Milestone 5]

### Owner answers (2026-09-23)

1. A walkover counts as a win and as a start. Races record the walkover so a clue can exclude walkovers.
2. Confirmed. The official result decides: a horse demoted from first counts as a loss, and a horse promoted to first counts as a win.
3. The racing-age table lists GB, IRE, FR, USA, CAN, JPN, GER, and HUN with 1 January, and AUS and NZ with 1 August. A country not in the table gives an unknown age. Age is computed under both the country of foaling and the country of the race. When the two ages differ, an age filter accepts the race if either age fits, and the timeline shows both.
4. Claude chooses the three fixture articles, following the suggested mix, and checks that each article uses the racehorse infobox before saving it.

Follow-up answers from milestone 1:

5. When a clue excludes walkovers, a walkover is skipped: it neither extends nor breaks a streak.
6. Japan's domestic grades compare equal to the G grades: Jpn1 is G1, Jpn2 is G2, Jpn3 is G3.
7. A void race does not count as a start. Claude's reading, not yet confirmed: a void race is left out of starts, wins, streaks, and the countries raced in, but stays in the race list for date order and the timeline.

## Milestone 0: housekeeping

Add `.gitignore`. Fix the five known issues listed in `CLAUDE.md`. Bench must still pass 9 of 9. Add `tests/` with a first `unittest` file covering `longest_win_streak`, `streak_then_loss`, `text_matches`, and `normalize_country`.

## Milestone 1: race record model

Add a `Race` dataclass and `Horse.races: Optional[List[Race]]`. Completeness uses `"races"` in `complete_fields`.

Suggested fields, all optional: `date` (ISO 8601, partial dates allowed: `"1875"`, `"1875-06"`, `"1875-06-12"`), `race` (name as published), `venue`, `country` (normalized suffix), `grade` (as published: `"G1"`, `"Grade 1"`, `"Listed"`), `distance_m`, `distance_text` (as published, e.g. `"1m 2f"`), `surface`, `finish` (official position, 1 = won), `outcome` (for example `finished`, `dead_heat`, `walkover`, `disqualified`, `promoted`, `fell`, `pulled_up`), `field_size`, `jockey`, `trainer`, `notes`, `source`.

Add a normalized grade helper so `"G1"`, `"Group 1"`, and `"Grade 1"` compare equal, while keeping the published text.

Derive the W/DH/L code for each race from `finish` and `outcome`, following the answers to questions 1 and 2.

Keep `results` as a valid field. When both `races` and `results` exist, validation requires the derived codes to match `results`. When only `races` exists, every evaluator that used `results` uses the derived codes instead. Races must be in career order; validation rejects dates that go backwards.

Derive starts, wins, and raced countries from `races` when those fields are not set directly and the race list is complete. Derived raced countries from a partial list can still produce a MATCH for `international`.

Check backward compatibility: export the V0.1 seed database, import it into V0.2, and confirm the bench still passes.

## Milestone 2: timelines and ages

Add `age_at(race)` using the racing-age table from question 3. It returns `None` when the foaling year or race date is unknown.

Add a `timeline ID` command that prints one line per race: date, age, race, venue, grade, finish, and the running win streak. Horses with only `results` print the sequence without dates.

## Milestone 3: race pattern clue

Add a `race` clue type with a filter and a quantifier.

The filter can use race name (with match mode), country, venue, grade, surface, year range, age range, and `abroad` (race country differs from the country of foaling).

Quantifiers and their tri-state rules:

| Quantifier | MATCH | CONTRADICTION | UNKNOWN |
|---|---|---|---|
| `won_any` | a matching race was won | races complete, no matching race won | otherwise |
| `lost_any` | a matching race was lost | races complete, every matching race won or none match | otherwise |
| `won_all` | races complete, at least one match, all won | any matching race lost, even in a partial list | otherwise |
| `count` (with `op`, `n`) | count settles the comparison | count settles the comparison | partial list where more races could change the result |
| `first` / `last` (with `result`) | races complete, first or last matching race has that result | races complete, it has the other result | races not complete |

A race with unknown date or country does not match a filter on that attribute and makes the finding UNKNOWN rather than CONTRADICTION when it could have mattered.

Update the `title` evaluator to also match won races by name, so a title can be proven from the race list.

Add fictional race-record horses to the seed data and at least six benchmark cases: won at age 4, lost on first start abroad, unbeaten at G1 level, `won_all` contradicted by a partial list, `first` left UNKNOWN on a partial list, and a title proven from races.

## Milestone 4: evaluator updates

Update `win_streak`, `loss_after_streak`, `unbeaten`, `career`, and `international` to use race records when present. Add unit tests with a truth table per evaluator covering complete records, partial records, summary only, and no data.

## Milestone 5: single-article Wikipedia importer

Add `import-wiki "Article title"`.

Fetch wikitext through the MediaWiki API with a descriptive User-Agent that names the tool and gives a contact, as Wikimedia's user-agent policy requires. Parse the infobox with `mwparserfromhell`, added as an optional extra (`pip install .[wiki]`) and imported lazily with a clear error if missing. This is the project's first dependency, so confirm with the owner before adding `pyproject.toml`.

Read the current documentation for the racehorse infobox template on Wikipedia before writing the field mapping. Do not guess template or parameter names.

Map what the infobox provides: name, foaling year, country, sex, sire, dam, trainer, jockey, owner, career record, major wins, and awards if useful. Store sire and dam in new optional fields for V0.4. Parse the career record defensively; if a format is not recognized, put the raw text in `notes` and leave `summary` unset.

Set `sources` for every imported field to the article URL, revision id, and retrieval date. Never mark any field complete. Never overwrite a field the owner already set unless `--overwrite` is given. Show a preview of the changes and ask for confirmation unless `--yes` is given.

Save the fixture articles from question 4 under `tests/fixtures/` with a short README giving each article's URL, revision id, and CC BY-SA attribution. Importer tests run against the fixtures only.
